(`authenticationCleartextPassword` and `authenticationMD5Password`), not credential

during the outage test, this is not recorded as a clean log-security check.

Database outage test:
Procedure: stop db, request /health, start db, then restart app to restore the stack.
Observed: app exited with code 1 after the PostgreSQL connection was interrupted;
curl received HTTP 000 (connection refused), not the expected sanitized 503 response.
The app log contained an unhandled pg pool error object/stack details.
Recovery: after starting db and app, both services became healthy and /health returned
HTTP 200 with {"status":"ok","db":"up"}.
Conclusion: DB-down error handling and log sanitization are NOT PASS; application fix
and re-test are required.
